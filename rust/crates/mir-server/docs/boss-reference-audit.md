# Boss reference audit

Reference: [Zircon-Godot, pinned commit cf61c82](https://github.com/iamcheyan/Zircon-Godot/blob/cf61c82ab4a2e4868b3806853ee81f451908bb11/ServerLibrary/Models/MonsterObject.cs). Local runtime database: `~/zircon-assets/Database/System.db` (read only). Audited 68 records with `IsBoss=true`, covering 42 AI IDs. Names and IDs below come from that database, not inferred image-to-AI mappings.

“Existing profile” means the AI is represented in Rust; it does not claim complete behavioral or visual equivalence. Targeted changes have regression tests in `world::monster_ai::report_tests`. The fork's existing boss classes match this repository's C# reference except castle classes; the fork additionally introduces Numa Warlord.

## Numa and Banya naming

- The installed Numa bosses are Numa Elder Shaman (#98, AI 26) and Numa Assault Captain (#166, AI 48). Their lightning and line-attack profiles already exist.
- The fork's [Numa Warlord](https://github.com/iamcheyan/Zircon-Godot/blob/cf61c82ab4a2e4868b3806853ee81f451908bb11/ServerLibrary/Models/Monsters/NumaWarlord.cs) uses AI 137 and image 196. A scan of all 309 installed monster definitions found zero records with AI 137 or image 196. Rust now supports its 500 ms delayed teleport (6 second cooldown), 400 ms delayed half-DC pull (10 second cooldown, up to three cells), and frontal sweep. Regression tests use a temporary in-memory definition; no runtime record was added. No other monster was silently remapped and no database records were invented.
- Banya Guardian (#114, image 147) is configured as AI 0. Emperor Sa'Woo (#115, AI 41) is the specialized Banya boss. The reference does not define a separate Banya Guardian boss class.

## Remaining limitations

The named fixes do not prove every boss behavior complete. Outstanding confirmed gaps are recorded explicitly in the table. In particular, Pachon/Guzak channeling, Tiger spin/warrior mitigation, Terracotta alternate melee, and the absent Numa Warlord database definition require separate work. Numa Warlord AI 137 is implemented and tested; only its runtime definition/spawn configuration is missing. The runtime packet currently carries one ranged target per message; multi-target visual delivery is not a full replica of the C# packet.
